# P3 切换与回滚手册

> 适用：把 `E:\erp-pm-soho`（Laravel 12 / PHP 8.3 / MySQL 8.4）从开发机切到公司内网服务器，替代 `erp / pm / soho` 三套旧站。
> 前置：P0~P3 已完成，`p3:verify` 全绿（见 `docs/数据校验报告.md`）。

---

## 一、环境基线

| 项 | 要求 |
|---|---|
| PHP | 8.3.x（`php -v` 必须 8.3，禁用 8.4） |
| 扩展 | pdo_mysql、mbstring、openssl、fileinfo、gd、zip、bcmath、intl、curl |
| MySQL | 8.4.x，字符集 `utf8mb4` / `utf8mb4_unicode_ci` |
| Web | Nginx 或 Apache，站点根目录指向 `public/`，开启 `index.php` 重写 |
| 必需目录可写 | `storage/`、`bootstrap/cache/` |
| 时区 | `Asia/Shanghai`（`APP_TIMEZONE=Asia/Shanghai`） |

`.env` 关键项（**不要提交进 Git**）：

```dotenv
APP_ENV=production
APP_DEBUG=false
APP_URL=https://erp.example.com
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=ddwl
DB_USERNAME=ddwl
DB_PASSWORD=******
SESSION_DRIVER=database
QUEUE_CONNECTION=database
CACHE_STORE=database
```

## 二、首次部署步骤

```powershell
# 1) 取代码
git clone https://github.com/yadxin789/erp-pm-soho.git /var/www/erp-pm-soho
cd /var/www/erp-pm-soho

# 2) 依赖（生产不带 dev）
composer install --no-dev --optimize-autoloader

# 3) 环境
cp .env.example .env
php artisan key:generate

# 4) 建库 + 建表（库需先建好，utf8mb4）
php artisan migrate --force

# 5) 缓存与索引
php artisan config:cache
php artisan route:cache
php artisan view:cache

# 6) 目录权限（Linux）
chown -R www-data:www-data storage bootstrap/cache
chmod -R 775 storage bootstrap/cache

# 7) 定时任务（crontab -e）
* * * * * cd /var/www/erp-pm-soho && php artisan schedule:run >> /dev/null 2>&1

# 8) 队列（supervisor，可选但聊天/通知/同步依赖）
php artisan queue:work --queue=default --sleep=3 --tries=3
```

## 三、数据补齐（切换前在目标库上执行，全部幂等）

```bash
php artisan p3:migrate-pm-org            # 演练：应为 0 部门 / 0 用户
php artisan p3:migrate-pm-org --apply    # 如源库仍有缺口则补齐
php artisan p3:fix-uniqueness            # 演练：缺邮箱 0 / 重复 0 组
php artisan p3:fix-uniqueness --apply
php artisan p3:verify --export-map --base=https://erp.example.com
```

`p3:verify` 必须 V1~V8 全绿；快照落在 `storage/app/p3-verify-*.json`。

## 四、切换步骤（建议选择业务低峰，总时长约 1 小时）

| 步 | 动作 | 责任 | 判定 |
|---|---|---|---|
| 1 | 旧三站置只读公告（或维护页），停止新业务写入 | 运维 | 公告已上线 |
| 2 | 全库备份旧三站（`mysqldump` 各自库 + SOHO sqlite 文件） | DBA | 备份文件可解压校验 |
| 3 | 备份目标库 `ddwl`（`mysqldump ddwl > ddwl_YYYYMMDD.sql`） | DBA | 文件大小 > 0 |
| 4 | 目标站执行第三节「数据补齐」 | 实施 | 全部幂等 0 变更 |
| 5 | 执行 `php artisan p3:verify --base=https://新站` | 实施 | V1~V8 全绿 |
| 6 | 反向代理/DNS 指向新站；旧站保留 30 天可回切 | 运维 | 域名解析生效 |
| 7 | 统一登录冒烟：ERP/PM/SOHO 各 1 个账号登录并落对应模块 | 实施 | 302 → `/erp` `/pm` `/soho` 200 |
| 8 | 三模块关键页巡检（每模块 10 页） | 实施 | 0×500 / 0×403 |
| 9 | 通知旧三站账号：新地址、新登录方式（username 或邮箱） | 行政 | 通知已发 |

## 五、切换后验收清单

- [ ] 首页三卡片（ERP / PM / SOHO）正常，未登录点击进统一登录页
- [ ] 统一登录：用户名、邮箱两种标识均可登录；禁用账号被拒
- [ ] 按部门自动跳模块：研发部→`/pm`，电商相关部门→`/soho`，其余→`/erp`，系统后台管理部→`/core`
- [ ] 无权限用户看不到入口（不出现 403 页）
- [ ] 文件预览 / 下载正常（`/files/{id}/preview`）
- [ ] 全局聊天、通知、我的待办可用；PM 项目内聊天/协同/电话会议可用
- [ ] ERP 采购→入库→库存→财务链路可走通（单据编号连续）
- [ ] SOHO 订单/库存/售后/退款链路可走通，`soho_platform_skus` 不再出现重复 SKU 报错
- [ ] 审计日志写入 `operation_logs`（`module` 归属正确），`soho_operation_logs` 视图可读
- [ ] 定时任务与队列在跑（`schedule:run` 无报错、`jobs` 表无堆积）

## 六、回滚

触发条件：切换后 30 分钟内出现数据错乱、登录大面积失败、核心单据不可用且 15 分钟内无法定位。

**代码回滚（回到上一提交）**

```bash
cd /var/www/erp-pm-soho
git log --oneline -5
git reset --hard <上一个稳定提交>
composer install --no-dev --optimize-autoloader
php artisan config:cache && php artisan route:cache && php artisan view:cache
```

**数据回滚（目标库）**

```bash
mysql -u root -p ddwl < /backup/ddwl_YYYYMMDD.sql
php artisan cache:clear && php artisan config:cache
```

**回切旧站（最稳路径）**

1. 反向代理/DNS 改回旧三站地址；
2. 旧站解除只读；
3. 校验旧站登录与核心单据；
4. 目标库保留现场不删，供后续复盘（`git revert` 而非强推）。

> 回滚只回退「部署」这一层，不回退已确认的业务数据口径；若涉及数据修复，先复制库再操作。
