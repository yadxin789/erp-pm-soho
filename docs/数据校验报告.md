## 五、限制与已知问题（不影响 P1/P2 结论，需在部署后复核）

1. **SOHO 源库不可比**：`E:\ddwl-soho` 为 `DB_CONNECTION=sqlite`，但其 `database/` 下已无任何 `.sqlite/.db` 文件（仅 factories/migrations/seeders）。全盘排查到的候选 sqlite（`E:\ddwl-shop`、`E:\soho\mysoho`、`E:\my-pm\pm-server-openEuler\database\database.sqlite`、`E:\ddwl-zm\ecmp`）均与 `admin@ddwl-soho.com` 等合并站 SOHO 账号不匹配；MySQL 库 `ddwl-zm`（23 users，`@ecmp.local`）为另一工程。故 SOHO 侧 V1 只能以「合并站自身 + 基线文档」为准（D21 已允许甩开参考目录）。
2. **`soho_platform_skus` 的 `platform_sku` 已唯一化（已修复）**：原 `(shop_id, platform_sku)` 有 4 组重复，每组 12 行（TB001-001 / JD001-002 / PDD001-003 等）。逐行核对 12 行的 `system_goods_id`(1..12)、`platform_goods_id`（PG722880…）、价格与库存**各不相同**，属种子把同一平台 SKU 复用到 12 个不同商品的演示数据特征。已按「保留首行、其余加 `-02…-12` 后缀」改写 44 行，并建组合唯一索引 `ux_platform_sku_shop(shop_id, platform_sku)`，现重复组 0。
3. **全员可登录（已修复）**：源 `pm_db.users` 无 email 列，合并站 50 个账号（PM 50 个）缺邮箱。已按 `<username>@pm.local` 补造 50 个（冲突自动加 `-N` 后缀），现 `users.email` 缺失 0、重复 0；统一登录页 `login` 字段同时命中 `email` 与 `username`，邮箱/用户名两条通道实测均可用。
4. `disabled_user`(#4) 解析为 core-only，属预期（禁用账号）；若后续启用，需补部门或 `user_module_access`。
5. `notifications` 中 1 条空 module 的 `private_message` 依赖 D15 的 core 可见规则；若后续收紧通知可见性，需回归该项。
